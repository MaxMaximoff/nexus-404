## Что это

Браузерное приложение для Roland **SP-404MKII**: загрузка сэмплов на pad'ы и редактирование BPM прямо из Chrome/Edge, без установки. Связь с устройством через **Web Serial**: у SP есть отдельное USB-устройство CDC-ACM `0582:02E7`, на Windows это COM-порт с драйвером `usbser`. WebUSB не подходит: интерфейс занят системным драйвером.

  - **темп и высота pad'а** (проверено на SP): BPM Sync, Vinyl, Stretch (скорость 50–150 %), Pitch ±12 st / ±100 ct; строка «фактическая скорость» (×1.29, удвоение/деление темпа pad'а за пределами 50–150 %, высота в st) — `sp404/tempo.ts`;
  - **темпы** (проверено на SP): в верхней панели переключатель «Проект / Банки» (`0B`) и одно поле темпа — при «Проект» это темп проекта (`0A`), при «Банки» темп банка, открытого в приложении (`21 + bank`); ещё поле темпа банка в заголовке сетки. После записи настройки проекта перечитываются;
  - волна в инспекторе;
  - **раскладка** (2026-10-07, пользователь одобрил «пока нормально»): две колонки — слева банки 2 × 5 и под ними сетка pad'ов (банки над сеткой с 2026-10-07), справа широкий инспектор-аккордеон (секции «Сэмпл» = волна + Start/End + trim, «Темп и высота», «Воспроизведение», «Файл»; открытые секции в localStorage `nexus404.inspector.open`; в свёрнутой секции сводка). Высота pad'а от высоты окна (`clamp(60px, (100dvh − 420px) / 4, 112px)`), так что верх, сетка, банки и инспектор помещаются в экран; импорт и журнал ниже, до них скролл. В инспекторе скроллятся только секции (`.insp-scroll`), заголовок pad'а и ряд «Прослушать / Стоп» всегда видны; скроллбары внутренних областей тонкие синие (`::-webkit-scrollbar`, приложение только для Chrome/Edge);
  - прослушивание на SP (удерживать кнопку) и **«Стоп» как кнопка паники** (проверено на SP): при Gate off SP игнорирует `8F`, поэтому `stopPad` = Gate 1 → `8E` → `8F` → Gate 0 (Gate восстанавливается в finally), потом на SP снова выбирается pad приложения. Кнопка красная, пока прослушанный pad может играть (`playing` в store); сигнал «доиграл» (`0E pad 64` по спецификации) не используется, не проверен;
  - **VARI MODE** (2026-10-07): селектор Off / Backing / Ensemble в «Темп и высота» с подсказками; при Vinyl on селектор серый (`.segmented.muted`), значение на SP сохраняется. Запись — биты 1–2 флагов `70`, остальные биты не трогаются. Запись с приложения проверена на SP (H2 → Backing);
  - очередь импорта с прогрессом, журнал (с опцией «показывать USB-кадры»).

## Запуск

```bash
cd app
npm install
npm run dev     # http://localhost:5173
npm test
npm run build   # dist/, статические файлы
```

- Dev-сервер настроен **без горячей перезагрузки** (`server.hmr: false`) по просьбе пользователя: Vite следит за файлами, но страница не обновляется сама, пользователь жмёт F5. Причина: перезагрузка рвёт serial-соединение, а горячая подмена модуля `store.ts` оставляла порт открытым у старой копии («The port is already open»).
- Перед подключением должен быть закрыт официальный SP-404MKII App: порт эксклюзивный. Разрешение на порт в Chrome привязано к origin: `localhost:5173` и `localhost:8000` — разные origin'ы.
- Превью-инструмент `preview_start` встроенного браузера в прошлой сессии искал `launch.json` в старой папке. Если снова не сработает, запускать `npx vite` через Bash в фоне.

## Безопасность (не нарушать)

- Все исходящие сообщения проходят `guard.ts`. Разрешено: чтение, preview (`8E`/`8F`), выбор банка/pad'а (`01 00|01 00 FF FF v`), per-pad set-parameter только из `PAD_PARAM_RANGE` в `control.ts` (Start `67`, End `68`, Level `69` 0–127, Gate `6A`/Loop `6B`/BPM Sync `6E` 0/1, BPM `6F` 4000–20000, флаги `70` 0–255, `72` только 0), глобальные из `GLOBAL_PARAM_RANGE` (темп проекта `0A`, Tempo Select `0B` 0/1, темпы банков `21`–`2A`, BPM 4000–20000; защита `17+bank` и громкость `35+bank` банков запрещены) и последовательность импорта **только для pad'а, который импортируется прямо сейчас**.
- Правки параметров (`SP404Device.editPad`): только текущий проект, не в меню, только непустой pad; после правки блок перечитывается. One Shot меняет только бит 5 флагов. Start/End проверяются по длине из заголовка SMP, порядок отправки сохраняет Start < End. Защищённые банки для правок параметров **не** блокируются (в SparkyMK2 блокируются). Пользователь BANK Protect не использует, вопрос отложен.
- **Запрещено:** `92` Init (стирает текущий проект, у SparkyMK2 был реальный инцидент), `91 pad 00 00` delete, `95` move, `35` rename (всегда переименовывает текущий проект), `02`, mkdir/rmdir/rename, запись чужих путей.
- Расширять guard только вместе с тестами и после эксперимента в песочнице.
- Импорт идёт только в **пустой** pad текущего проекта (проверяется статусом прямо перед записью). Если SP в меню (working mode ≠ 0), запись блокируется.
- Лицензия: SparkyMK2 под GPL. Наш код написан по спецификации `docs/re`, а не переводом их кода. Сохранять этот подход, если нужна не-GPL лицензия.

## Важные находки (подробно в отчёте §0)

- Импорт нашим клиентом **побайтно совпадает** с импортом официальным App: в блоке pad'а меняются только size, start = 512, end, loop top = 512 и имя (дополняется нулями, до 23 символов).
- **`8E` играет pad, выбранный НА УСТРОЙСТВЕ**, и только потом переключает выбор. Поэтому клиент выбирает pad на SP при каждом клике (`selectOnDevice`), как App.
- Сразу после смены проекта на SP блоки pad'ов читаются **пустыми**, пока проект грузится. Клиент ждёт уведомление `1A` или 2,5 с после изменения статуса.
- Поле pad block f27 — копия BPM, снятая при загрузке проекта, не хранится. **VARI MODE = биты 1–2 флагов `70`**: Off 0, Backing `0x02`, Ensemble `0x04` (дампы `captures/vari-H1..H5.txt`: банк H проекта 4, один сэмпл с разными настройками). `6C` = 1 всегда, не VARI. SP хранит VARI и при Vinyl on.
- Правки, сделанные кнопками на SP (например, Gate), **не пережили** выключение питания. Удалённые правки (импорт, BPM, Level, Gate, Loop, One Shot, Start/End) пережили.
- Разрешение Web Serial сохраняется после перезапуска Chrome и переподключения кабеля, хотя у порта нет USB serial number.
- Байты 13–18 статуса `02 01 00 00 0b 33` не меняются. Это кандидат на версию прошивки, не проверено.
- Ловушки окружения:
  - PowerShell: имена переменных не различают регистр (`$pad` = `$Pad`);
  - в Vite 8 нет `import.meta.hot.decline()`;
  - TypeScript 7 (`tsc` работает как обычно);
  - клон SparkyMK2 требует `core.longpaths`.

## Следующие шаги (пользователь выбирает, рекомендован №1)

0. ~~VARI MODE~~ — найдено, сделано и проверено на SP (см. «Состояние»). Исходный план был: По руководству Roland (reference v2.00, стр. 31836436): Off / Backing (звуки с затуханием: drums, percussion, guitar strumming) / Ensemble (тянущиеся: choir, strings); доступен только при VINYL MODE = No; на SP: меню PITCH/SPEED, [SHIFT] + [VALUE]. В спецификации SparkyMK2 id нет. Кандидат — поле 6, id `6C` («unknown, 1 on every loaded pad»). План, только чтение: пользователь жмёт «Отключить» в приложении (порт эксклюзивный) → `tools/sp404-probe.ps1 -Pad F7 -Save captures/P4-F7-vari-before.txt` → пользователь меняет VARI MODE у F7 кнопками на SP (Vinyl off) → дамп `-after` → diff. Потом: guard + тест, селектор в «Темп и высота» (неактивен при Vinyl) с подсказками «Backing — drums / rhythmic», «Ensemble — sustained / tonal». Ещё из руководства: BPM SYNC бывает AUTO или MANU — разобраться, что это в блоке.
0. ~~Реакция сэмпла на темп~~ — сделано и проверено на SP: блок «Темп и высота» (BPM Sync, Vinyl `77`, Stretch `76` = скорость в %, Pitch `73`/`74`; Pitch неактивен при Vinyl). Vinyl 1 — темп меняет высоту, Vinyl 0 — time-stretch. SP держит отношение скоростей BPM Sync в 50–150 % и удваивает/делит темп лупа за пределами (отчёт §0). Идея: показывать в инспекторе фактическую скорость pad'а при текущем темпе.
