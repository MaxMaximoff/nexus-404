## Что это

Браузерное приложение для Roland **SP-404MKII**: загрузка сэмплов на pad'ы и редактирование BPM прямо из Chrome/Edge, без установки. Связь с устройством через **Web Serial**: у SP есть отдельное USB-устройство CDC-ACM `0582:02E7`, на Windows это COM-порт с драйвером `usbser`. WebUSB не подходит: интерфейс занят системным драйвером.

## Состояние

- **Исследование закрыто.** Вердикт «A: browser-only реализуем», подтверждён на реальном железе. Полный отчёт с источниками и результатами экспериментов: `SP404MKII-browser-feasibility.md`. Начинать с §0 (что проверено на нашем SP), затем §8 (что открыто) и §9 (MVP).
- **MVP v0.1 работает на реальном SP** (`app/`, Vite 8 + TypeScript 7 + Preact 11 + @preact/signals, тесты на vitest 5):
  - подключение и автоподключение, в том числе после того, как выдернули кабель;
  - чтение всех 160 pad'ов меньше чем за 0,5 с;
  - drag & drop одного или нескольких файлов на пустой pad: файлы ложатся на него и следующие пустые pad'ы банка;
  - BPM из имени файла (`loop_96bpm.wav`) или из поля «BPM новых сэмплов»;
  - декодирование любого формата в 48k/16 (WAV 48k/16 копируется bit-exact, остальное через `decodeAudioData`), mono сохраняется как 1 канал;
  - редактирование BPM: поле, Enter;
  - **параметры pad'а** (v0.2, проверено на SP, переживают выключение питания): Level (ползунок), Gate, Loop, One Shot, BPM Sync (переключатели; One Shot как в App гасит Gate/Loop/`72`), Start/End в секундах, перетаскиванием маркеров на волне (запись при отпускании; зум колесом вокруг курсора, сдвиг Shift+колесом или перетаскиванием пустого места, кнопки −/+/Весь/→ Start/→ End — окно 100 мс вокруг маркера; в зуме волна строится из PCM, PCM хранится для 16 последних волн), кнопкой «Весь сэмпл» и кнопкой «Убрать тишину» (только маркеры, файл не меняется; поиск по огибающей блоками по 32 кадра по всему сэмплу, порог −60/−48/−36/−24 dB, по умолчанию −36 — выбран пользователем на слух);
  - волна в инспекторе;
  - прослушивание на SP (удерживать кнопку);
  - очередь импорта с прогрессом, журнал (с опцией «показывать USB-кадры»).

## Запуск

```bash
cd app
npm install
npm run dev     # http://localhost:5173
npm test
npm run build   # dist/, статические файлы
```

- Dev-сервер настроен **без горячей перезагрузки** (`server.hmr: false`) по просьбе пользователя: Vite следит за файлами, но страница не обновляется сама, пользователь жмёт F5. Причина: перезагрузка рвёт serial-соединение, а горячая подмена модуля `store.ts` оставляла порт открытым у старой копии («The port is already open»).
- Перед подключением должен быть закрыт официальный SP-404MKII App: порт эксклюзивный. Разрешение на порт в Chrome привязано к origin: `localhost:5173` и `localhost:8000` — разные origin'ы.
- Превью-инструмент `preview_start` встроенного браузера в прошлой сессии искал `launch.json` в старой папке. Если снова не сработает, запускать `npx vite` через Bash в фоне.

## Безопасность (не нарушать)

- Все исходящие сообщения проходят `guard.ts`. Разрешено: чтение, preview (`8E`/`8F`), выбор банка/pad'а (`01 00|01 00 FF FF v`), per-pad set-parameter только из `PAD_PARAM_RANGE` в `control.ts` (Start `67`, End `68`, Level `69` 0–127, Gate `6A`/Loop `6B`/BPM Sync `6E` 0/1, BPM `6F` 4000–20000, флаги `70` 0–255, `72` только 0) и последовательность импорта **только для pad'а, который импортируется прямо сейчас**.
- Правки параметров (`SP404Device.editPad`): только текущий проект, не в меню, только непустой pad; после правки блок перечитывается. One Shot меняет только бит 5 флагов. Start/End проверяются по длине из заголовка SMP, порядок отправки сохраняет Start < End. Защищённые банки для правок параметров **не** блокируются (в SparkyMK2 блокируются). Пользователь BANK Protect не использует, вопрос отложен.
- **Запрещено:** `92` Init (стирает текущий проект, у SparkyMK2 был реальный инцидент), `91 pad 00 00` delete, `95` move, `35` rename (всегда переименовывает текущий проект), `02`, mkdir/rmdir/rename, запись чужих путей.
- Расширять guard только вместе с тестами и после эксперимента в песочнице.
- Импорт идёт только в **пустой** pad текущего проекта (проверяется статусом прямо перед записью). Если SP в меню (working mode ≠ 0), запись блокируется.
- Лицензия: SparkyMK2 под GPL. Наш код написан по спецификации `docs/re`, а не переводом их кода. Сохранять этот подход, если нужна не-GPL лицензия.

## Важные находки (подробно в отчёте §0)

- Импорт нашим клиентом **побайтно совпадает** с импортом официальным App: в блоке pad'а меняются только size, start = 512, end, loop top = 512 и имя (дополняется нулями, до 23 символов).
- **`8E` играет pad, выбранный НА УСТРОЙСТВЕ**, и только потом переключает выбор. Поэтому клиент выбирает pad на SP при каждом клике (`selectOnDevice`), как App.
- Сразу после смены проекта на SP блоки pad'ов читаются **пустыми**, пока проект грузится. Клиент ждёт уведомление `1A` или 2,5 с после изменения статуса.
- Поле pad block f27 — копия BPM, снятая при загрузке проекта, не хранится. Смысл бита 2 во флагах (`70`) неизвестен.
- Правки, сделанные кнопками на SP (например, Gate), **не пережили** выключение питания. Удалённые правки (импорт, BPM, Level, Gate, Loop, One Shot, Start/End) пережили.
- Разрешение Web Serial сохраняется после перезапуска Chrome и переподключения кабеля, хотя у порта нет USB serial number.
- Байты 13–18 статуса `02 01 00 00 0b 33` не меняются. Это кандидат на версию прошивки, не проверено.
- Ловушки окружения:
  - PowerShell: имена переменных не различают регистр (`$pad` = `$Pad`);
  - в Vite 8 нет `import.meta.hot.decline()`;
  - TypeScript 7 (`tsc` работает как обычно);
  - клон SparkyMK2 требует `core.longpaths`.
