## Что это

Браузерное приложение для Roland **SP-404MKII**: загрузка сэмплов на pad'ы и редактирование BPM прямо из Chrome/Edge, без установки. Связь с устройством через **Web Serial**: у SP есть отдельное USB-устройство CDC-ACM `0582:02E7`, на Windows это COM-порт с драйвером `usbser`. WebUSB не подходит: интерфейс занят системным драйвером.

  - **раскладка** (2026-10-07, пользователь одобрил «пока нормально»): две колонки — слева банки 2 × 5 и под ними сетка pad'ов (банки над сеткой с 2026-10-07), справа инспектор. **С 2026-10-07 — вкладки вместо аккордеона** (аккордеон перерос 7 секций): шапка — имя pad'а и корзина, строка о файле (`1.25 s · stereo · 0.23 MB`, секции «Файл» больше нет), чипы «особенного» (BPM всегда, остальное — только когда не обычное: Sync, Vinyl/VARI, Stretch, Pitch, Level, Bal, Gate off, Loop, One Shot, Fixed Vel, направление, AHR, M x, L x, BUS FX ≠ 1; клик открывает вкладку); вкладки «Сэмпл» (волна, Start/End, «Убрать тишину» + карточка «Темп и высота») · «Pad» (Level, Balance, переключатели, Play + карточка «Огибающая») · «Микс» (Mute Group, PAD Link, BUS FX, Roll) · отдельно справа «⚡ Ресэмпл» (операция, а не свойство). Содержимое вкладок не размонтируется (`hidden`), поэтому зум волны и введённое сохраняются; выбранная вкладка в localStorage `nexus404.inspector.tab`; уход с «Ресэмпла» закрывает вход записи. Высота pad'а от высоты окна (`clamp(60px, (100dvh − 420px) / 4, 112px)`), так что верх, сетка, банки и инспектор помещаются в экран; импорт и журнал ниже, до них скролл. ## Безопасность (не нарушать)

- Все исходящие сообщения проходят `guard.ts`. Разрешено: чтение, preview (`8E`/`8F`), выбор банка/pad'а (`01 00|01 00 FF FF v`), per-pad set-parameter только из `PAD_PARAM_RANGE` в `control.ts` (Start `67`, End `68`, Level `69` 0–127, Gate `6A`/Loop `6B`/BPM Sync `6E` 0/1, BPM `6F` 4000–20000, флаги `70` 0–255, `72` только 0), выбор проекта `9A p 00` (p < 16; SP только загружает другой проект, ничего не пишет), перенос pad'а `95 src dst mode` (mode 1 = обмен — всегда; mode 0 = перенос — только на pad, который `movePad` только что проверил пустым: `policy.moveToEmpty`; mode 0 на занятый pad стирает его сэмпл и не отправляется никогда), удаление `91 pad 00 00` только для pad'а, который `deletePad` только что проверил (непустой, текущий проект, не меню, банк не защищён): `policy.deletePad`, глобальные из `GLOBAL_PARAM_RANGE` (темп проекта `0A`, Tempo Select `0B` 0/1, темпы банков `21`–`2A`, BPM 4000–20000; защита `17+bank` и громкость `35+bank` банков запрещены) и последовательность импорта **только для pad'а, который импортируется прямо сейчас**.
- Правки параметров (`SP404Device.editPad`): только текущий проект, не в меню, только непустой pad; после правки блок перечитывается. One Shot меняет только бит 5 флагов. Start/End проверяются по длине из заголовка SMP, порядок отправки сохраняет Start < End. Защищённые банки для правок параметров **не** блокируются (в SparkyMK2 блокируются). Пользователь BANK Protect не использует, вопрос отложен.
- **Запрещено:** `92` Init (стирает текущий проект, у SparkyMK2 был реальный инцидент), `91 pad 00 00` для любого pad'а, кроме только что проверенного и подтверждённого пользователем, `95` overwrite (mode 0 на занятый pad), `35` rename (всегда переименовывает текущий проект), `02`, mkdir/rmdir/rename, запись чужих путей.
- Расширять guard только вместе с тестами и после эксперимента в песочнице.
- Импорт идёт только в **пустой** pad текущего проекта (проверяется статусом прямо перед записью). Если SP в меню (working mode ≠ 0), запись блокируется.
- Лицензия: SparkyMK2 под GPL. Наш код написан по спецификации `docs/re`, а не переводом их кода. Сохранять этот подход, если нужна не-GPL лицензия.

## Важные находки (подробно в отчёте §0)

- Импорт нашим клиентом **побайтно совпадает** с импортом официальным App: в блоке pad'а меняются только size, start = 512, end, loop top = 512 и имя (дополняется нулями, до 23 символов).
- **`8E` играет pad, выбранный НА УСТРОЙСТВЕ**, и только потом переключает выбор. Поэтому клиент выбирает pad на SP при каждом клике (`selectOnDevice`), как App.
- Сразу после смены проекта на SP блоки pad'ов читаются **пустыми**, пока проект грузится. Клиент ждёт уведомление `1A` или 2,5 с после изменения статуса.
- Поле pad block f27 — копия BPM, снятая при загрузке проекта, не хранится. **VARI MODE = биты 1–2 флагов `70`**: Off 0, Backing `0x02`, Ensemble `0x04` (дампы `captures/vari-H1..H5.txt`: банк H проекта 4, один сэмпл с разными настройками). `6C` = 1 всегда, не VARI. SP хранит VARI и при Vinyl on.
- Правки, сделанные кнопками на SP (например, Gate), **не пережили** выключение питания. Удалённые правки (импорт, BPM, Level, Gate, Loop, One Shot, Start/End) пережили.
- Разрешение Web Serial сохраняется после перезапуска Chrome и переподключения кабеля, хотя у порта нет USB serial number.
- Байты 13–18 статуса `02 01 00 00 0b 33` не меняются. Это кандидат на версию прошивки, не проверено.
- Ловушки окружения:
  - PowerShell: имена переменных не различают регистр (`$pad` = `$Pad`);
  - в Vite 8 нет `import.meta.hot.decline()`;
  - TypeScript 7 (`tsc` работает как обычно);
  - клон SparkyMK2 требует `core.longpaths`.

Сценарий: вход открывается при необходимости → `capture` (rec.ts) → 150 мс → `previewStart` (8E) → длина Start–End / скорость pad'а (`padSpeed` при текущем темпе) → отпускание (`previewStop`; при Gate off + Loop — `stopPad`) → хвост → обрезка/нормализация → дубль `<имя>_rs` (`TakeCard`) с BPM = BPM pad'а × скорость (импорт с источником BPM «от исходного pad'а», `importFiles(…, bpmX100)`) → «На H2» или перетащить на пустой pad. **Не проверено:** идёт ли 8E через эффекты SP (в эксперименте pad нажимали руками), задержка/обрезка начала, Loop/Gate-случаи. **PAD Link (для лееринга, просьба пользователя):** длительность записи — по самому длинному pad'у группы (`linkedPads`, в секции пояснение «PAD Link B: H1, C9, H5 звучат вместе»). **Проверено на SP: `8E` запускает только один pad, и прослушивание одноголосое** — пачкой (выборы + `8E` одной записью) играл только первый pad, по одному с ожиданием ответов — только последний: каждый новый `8E` глушит предыдущий. Сообщения `0E pad 64` и `0F 00 00 64` приходят сразу после запуска (смысл `64` неясен). Слои командой `8E` не собрать — код пачки удалён. **Теперь (проверено на SP: J1 + J2 из PAD Link B звучат оба):** запуск по MIDI (`ui/midi.ts`, Web MIDI, порт с «SP-404» в имени): нота-on 127 на pad, как рукой — SP должен сам сыграть группу PAD Link; карта нот из экспорта паттернов SparkyMK2 (04-patterns.md): канал = банк (A=1…J=10), нота = 36 + место в сетке снизу вверх (pad 13 = 36, pad 1 = 48) — это «MIDI mode A» Roland (ноты 35–51, у каждого банка свой канал; работает на SP пользователя); в режиме B ноты 12–91 и другая карта. Запуск только MIDI-нотой (переключатель «MIDI / команда» убран по просьбе пользователя, путь `8E` удалён). Галочка «убрать тишину» убрана: на аналоговом входе шум выше фиксированного порога −60 dB, обрезка не срабатывала; пауза перед ударом сокращена до 50 мс; тишину пользователь снимает после импорта кнопкой «Убрать тишину» (маркеры). Интересно на будущее: SparkyMK2 описывает MULTIPAD/Bounce — SP сам рендерит паттерн в WAV и пишет его на хост через файловое API (04-patterns.md). **Ресэмпл группы** (2026-10-07, сделано и проверено на SP): в групповом инспекторе секция «Ресэмпл через эффекты SP» — выделенные pad'ы по очереди через текущий эффект SP (`resampleGroup`, общий `recordPad`), дубли копятся в памяти и одним `importFiles` ложатся на первые пустые pad'ы выбранного банка (SP не пишет файлы, пока играет), BPM у каждого свой (`importFiles(…, bpm[])`); план «J1 → A1, J3 → A2» виден заранее, при нехватке пустых — кнопка неактивна; pad, который звучит слоем PAD Link более раннего выбранного, пропускается (`groupPlan`); прогресс «Ресэмпл 2 из 3» над сеткой, «Стоп» — после текущего pad'а, записанное импортируется. Дальше, опционально: MIDI-управление эффектами. Потом, опционально: управление эффектами SP по MIDI из браузера (Web MIDI), пресеты.

12. **Эффекты SP по MIDI — изучено 2026-10-07, отложено:** пользователю пока проще крутить ручки на самом SP. План на потом — эксперимент (CC#83 на BUS 1 + Ctrl 1, слежение за CC с SP) → панель эффектов → пресеты и ресэмпл через пресет. По MIDI Implementation Roland (v5, 2025) и таблице «Control change messages and corresponding effects» (reference v5.50): канал 1–4 = BUS 1–4, канал 5 = INPUT FX (с нотами pad'ов не конфликтует — другой тип сообщений). CC#83 — номер эффекта (BUS1/2: 0 OFF … 42 DJFX Delay; BUS3/4: 0 … 40 DJFX Delay, свой порядок; INPUT: 0 … 17), CC#19 — EFX вкл/выкл (0–63/64–127), CC#16/17/18/80/81/82 — Ctrl 1–6 (0–127). SP эти CC и **передаёт** при вращении ручек (можно следить), и принимает. **SysEx нет** — текущее состояние эффектов не прочитать при подключении, приложение знает только то, что задало само или увидело. Названия параметров Ctrl 1–6 у каждого эффекта свои — только из руководства. В DJ-режиме каналы другие (*7). В проекте есть `Efct.{BusRouting,BusAssign,Limit,DirectFx1..5,SubParam4..6}` (строки App, SparkyMK2 00-findings) — где лежат, неизвестно. Идеи: панель эффектов (шина, эффект, вкл, 6 ручек), пресеты (эффект + ручки) и ресэмпл «через пресет» — повторяемый результат для группы.

13. **Паттерны** (2026-10-08). Формат — `SparkyMK2/docs/re/04-patterns.md`; сверено на SP (проект 4: A1, G1, G2, G5, G6 — 4 такта и 1 такт).
   **Новое против спецификации:** velocity разная (25–127, у SparkyMK2 всегда 127); длина в тактах — в байтах 0 **и 6** хвоста (у них байт 6 «всегда 4»); ноты с высотой `0x8D`/`0x8F` (в G6); бит `0x40`/`0x41` в байте группы стоит на первой ноте каждого файла (смысл не ясен). Цепочки `PATTERNCHAIN_00.CHN` в проекте 4 нет. Путь чтения — как у сэмплов (`remotePath`: `/SP404REMOTE///ROLAND/…`).
   **Опыты на SP (2026-10-08, A2 и A3 записаны пользователем в TR-REC):** байт 3 — высота: TR-REC пишет `0x80 | (13 + полутоны)` в каждую ноту (`0x8D` = исходная, шаг +1 → `0x8E`), у живой записи 0; сила удара TR-REC по умолчанию 90, длина 119; флаг `0x40` на первой ноте — у живой записи. **Sub-step** TR-REC пишет обычными нотами внутри шага (1/2 → 2 ноты через 60 тиков, длина 59; 1/3 → через 40, длина 39; 1/4 → через 30, длина 29), то есть они уже есть в сетке и в MIDI. Записи типа `0x80` с данными ноты («пустая запись с данными» из спецификации) — по-видимому, **затёртые события**: после смены значения sub-step старые удары остаются в файле с типом `0x80` (длина 29 от прежнего 1/4 рядом с нотами 1/3). Запись `…FF` встретилась и в TR-REC-паттерне A3 (рядом с живой нотой A3), смысл не ясен. **Разбор sub-step отложен пользователем** (не важен на этом этапе); если вернёмся — спросить, какие значения стояли на шагах 3, 7, 11, 15 паттерна A3 и менялись ли они несколько раз.
   **Этап 1 сделан (только чтение, guard не менялся):** паттерны читаются вместе с проектом (`listDir` PTN/ + `readFile`), кнопка «Паттерны» в верхней панели: матрица 160 слотов (A–E слева, F–J справа, как группы SP) и пошаговая сетка — строки pad'ы, столбцы шаги 1/16, ноты вне сетки рисуются где есть, «вне сетки 1/16: N»; метка `P n` на pad'е, «В паттернах: …» в инспекторе, предупреждение при удалении; экспорт MIDI как у SP, но с темпом, который играет сейчас (проект/банк). **На SP в приложении не проверено** (вид проверен на данных с SP, подставленных в страницу).
   **Открыто:** переводит ли SP ноты паттернов при переносе pad'а — после переноса паттерны перечитываются, ответ пишется в журнал (`reportPatternsAfterMove`).
   **Этап 2 — Bounce сделан и проверен на SP (G6: 2.00 s при ожидаемых 2.00 s, WAV 48k/16 стерео, звучит как паттерн):** `SP404Device.bouncePattern` — `FB 00 00`, `B8 slot 1000 0`, `B8 slot 1003 0`, ответы на запись/seek SP в наш файл (`HOST_ACK` + `hostStatus`), прогресс — эхо глобального `86`, опрос `FE 66 00` каждые 500 мс, по `39` — `B8 slot 1001 0`, `FC 00 00` (всегда, и при ошибке). Guard: `policy.renderPattern` — только этот слот, только ops 1000/1001/1003 и handle 0, только наши ответы на канале 6. В UI: «Bounce в WAV» под сеткой → дубль (`TakeCard`: прослушать, «На pad» с BPM темпа, который играл) и «WAV» как прислал SP. Не проверено: идут ли эффекты SP в Bounce. **MULTIPAD** (рендер по pad'ам, ops 0–159) — guard пока закрывает.
   **Дальше:** редактор паттернов **редактор паттернов в стиле TR-REC, но удобнее** (просьба пользователя) — сетка этапа 1 задумана как его основа. Запись паттернов на SP — отдельный этап: **потеря данных допустима, поломка SP — нет**: guard пускает только точный путь `PTN/PTNnnnnn.BIN`, неразобранные команды (`AD`/`AE`/`AF`/`B0`) не слать, сначала копировать готовый файл SP байт в байт, опыты в проекте, который SP не грузит при включении; нужен захват импорта паттерна официальным App.
